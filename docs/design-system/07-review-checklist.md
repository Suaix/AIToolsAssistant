# L7 · 设计走查清单（Design Review Checklist）

> **这是一份"封顶文档"——所有新页面、新组件、新迭代都必须过这张清单。**  
> 通过 = 合并；不通过 = 回退修改。  
> 走查不是"可选的礼节"，是"保证设计系统不崩的最后一道闸"。

## 📋 如何使用本清单

### 1. 新增一个页面时

- 完成开发后，**对照本清单逐条打勾**
- 任何一项未过 = 不允许合并
- 清单未覆盖到的模糊场景，回溯 L1~L5 查依据

### 2. 迭代已有页面时

- 改动范围内的相关项必须重新过一遍
- 如果改动的是"组件"层级（非页面），优先改 L5 规范，再改实现

### 3. 每季度全面走查一次

- 随机抽 1-2 个页面，按清单逐条复查
- 发现规范漂移 = 回到 L4/L5 补充/修订

## ✅ 走查清单（按 4 条原则分组）

### 🧭 L2 原则 1 · 状态先于功能

- [ ] **首屏最显眼的元素是"状态"而非"操作按钮"**
  - 状态卡 / 徽章 / Hero 必须在视觉主位
  - 主操作按钮不能比状态元素更大、更抢眼
- [ ] **所有列表页有清晰的"整体状态指示"**
  - 顶部告知"共 N 项，M 项需更新"
  - 不能让用户挨个点开才知道"有没有问题"
- [ ] **所有加载态、异步态都有明确的 loading / skeleton**
  - 不允许空白 + spinner 旋转超过 2 秒
- [ ] **所有空状态遵循 L5 EmptyState 组件规范**
  - 必含：图标 + 标题 + 描述 + CTA
  - 无 CTA 的空状态（如"搜索无结果"），必须写明"下一步怎么办"

### 🎯 L2 原则 2 · 明确先于惊喜

- [ ] **页面内所有动效时长 ≤ 400ms**（仅同步魔法动效 ≤ 640ms 例外）
- [ ] **没有装饰性动画**（无信息价值的动画 = 装饰）
  - ❌ 数字翻牌、3D 翻转、粒子特效、视差滚动
- [ ] **所有加载 spinner 仅在 ≥ 400ms 等待时显示**，避免闪烁
- [ ] **路径、hash、版本号全部使用等宽字体** (`font-mono` class)
- [ ] **表格、状态数字使用 `tabular-nums`**
- [ ] **尊重系统 `prefers-reduced-motion`**（已由 tokens.css 保证，只需不打破）

### 💎 L2 原则 3 · 诚实先于友好

- [ ] **错误文案必须包含"原因 + 操作路径"**
  - ✅「CodeBuddy 未连接。路径不存在：`~/.codebuddy/`。检查路径」
  - ❌「出错了，请稍后重试」
- [ ] **失败类 Toast 永不自动消失**（必须用户手动关闭）
- [ ] **失败有留痕**：Toast 消失后，同步中心 / 详情页历史中必须还能看到
- [ ] **未实现的功能用 `—` 或"未支持"明示**，不藏、不灰禁用+不告知
- [ ] **禁用 Emoji 装饰**（🎉 ✨ 🚀 等），仅状态 Icon 允许
- [ ] **禁用"哎呀/噢豁/稍后再试/小问题"等糊弄话术**

### 🪶 L2 原则 4 · 克制先于全面

- [ ] **每屏只有一个 Primary 按钮**
- [ ] **页面信息层级 ≤ 3 级标题**（H1 → H2 → H3）
- [ ] **没有"Beta / 即将推出 / Coming Soon"标记**（不做期货）
- [ ] **没有"高级设置 / 更多选项"折叠区**（要么做到面上，要么不做）
- [ ] **一个卡片内的 Footer 操作按钮 ≤ 3 个**
- [ ] **Dashboard 不堆砌统计小部件**（Hero 之外只有"最近活动" + "工具摘要"）

## 🎨 视觉规范检查

### L4 视觉语言合规

- [ ] **所有颜色都来自 tokens.css 语义变量**，没有硬编码 HEX
- [ ] **没有行内 `style=""` 写颜色**（允许写布局间距，但不允许写颜色）
- [ ] **圆角 ≥ 4px**，主要交互元素 ≥ 8px
- [ ] **阴影最多 1 层**，不堆叠
- [ ] **主色 Teal 占页面 ≤ 15%**，不大面积铺陈
- [ ] **状态色 Mint/Amber/Rose 占页面 ≤ 5%**
- [ ] **暗色模式完整支持**，切换无断裂
- [ ] **三层背景深度正确**（暗：950 画布 / 900 主区 / 800 卡片）

### L5 组件规范合规

- [ ] **所有组件只使用 components.css 已定义的类名**
- [ ] **没有自创组件变体**（需要新变体 = 回 L5 补规范）
- [ ] **按钮层级正确**：Primary 1 个 + Secondary 多个 + 图标按钮有 `aria-label`
- [ ] **状态徽章**同时用"颜色 + 圆点 + 文字"三元素
- [ ] **Toast 失败态** `role="alert"` 且 `persist: true`
- [ ] **Modal** 有 `role="dialog"` + `aria-modal="true"` + 聚焦管理

---

## ♿ 可访问性检查

- [ ] **所有交互元素可 Tab 聚焦**
- [ ] **焦点环可见** `var(--shadow-focus)`
- [ ] **Enter / Space 触发按钮**
- [ ] **Esc 关闭 Modal / 弹层**
- [ ] **图标按钮有 `aria-label`**
- [ ] **对比度 ≥ 4.5:1**（正文） / **≥ 3:1**（大字号、图标）
- [ ] **色盲模拟测试**：Deuteranopia（绿色盲）下状态仍可区分（靠文字 + 圆点形状）
- [ ] **键盘完成所有核心流程**，不依赖鼠标

---

## 📝 文案检查

- [ ] **按钮文案动词开头**，3~6 字为佳
- [ ] **不出现"请/您/感谢/抱歉"** 等客套词（除非正式邮件模板）
- [ ] **路径、命令、代码用反引号或等宽字体**
- [ ] **数字带单位**（"12 Skill" 而非 "12"）
- [ ] **时间用相对时间**（"2 分钟前" 而非精确时间戳），除非用户明确需要精确值

---

## 🎬 交互检查

- [ ] **任何破坏性操作**（删除、断开、清空）必须有 Modal 二次确认
- [ ] **Modal 按钮主操作在右**（macOS 习惯）
- [ ] **Tab 切换保留当前状态**（不重置滚动、不重置表单）
- [ ] **搜索类输入有 300ms debounce**，避免过度请求
- [ ] **页面跳转保留侧栏状态**（当前页高亮、展开状态）

---

## 📐 响应式 / 尺寸检查

- [ ] **主窗口最小 800 × 600 可用**
- [ ] **侧栏 < 900px 时自动折叠为图标模式**
- [ ] **Popover 固定 400 × 560**，不随窗口变
- [ ] **Modal 内容过长时有滚动**，而非撑破视窗
- [ ] **长文本有省略或换行处理**（卡片描述 ≤ 2 行）

---

## 🧪 评审流程建议

### 自查（开发者本人）

1. 完成功能 → 打开对应页面
2. 按本清单**每一项逐个点**（不要跳）
3. 发现问题 → 修复 → 重查
4. 全通过 → 提 PR

### 同行评审（Pair Review）

1. Review 人打开**浏览器 + 本清单**
2. 至少覆盖"4 条原则检查"和"视觉规范检查"两大节
3. 任一项不通过，Request Changes
4. 全通过，LGTM

### 季度全量走查

1. 抽取 1-2 个页面（优先覆盖率低的）
2. 按完整清单过一遍
3. 发现规范漂移 → 在 L4/L5 补充缺失的规则
4. 把新学到的 case 沉淀到本清单的"具体例子"里

## 🚦 红灯条款（必须一票否决）

以下问题**无论其它多好**都不允许合并：

1. ❌ 未实现的功能显示"Coming Soon"
2. ❌ 错误提示用 "出错了，请稍后重试" 这类糊弄文案
3. ❌ 行内写死品牌色或状态色 HEX
4. ❌ 破坏性操作无二次确认
5. ❌ 暗色模式下某个元素"看不见"或"烧眼"
6. ❌ 首屏没有状态元素，只有一堆操作按钮
7. ❌ 同一屏出现 2 个以上 Primary 按钮
8. ❌ 任何动效 > 800ms（同步魔法除外）
