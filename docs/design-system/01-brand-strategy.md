## 一、产品定义（Product Definition）

### 1.1 一句话定义（Slogan）

> **你写一次，它到处都在。**
>
> *Write once. Sync everywhere.*

**备用正式描述**（用于官网介绍、README 首行等需要解释性表达的场景）：

> 一次配置，同步到所有需要的地方。

### 1.2 一段话定义（Elevator Pitch）

AIToolsAssistant 是一款**面向多 AI 助手用户**的桌面应用。你在一个地方写好你的 Skill、Prompt、Rule，它会**自动同步到你使用的每一个 AI 编程助手和每一个项目**中。你不再需要复制粘贴，也不再担心哪个工具用的是旧版本——打开应用，一眼就能看到"**所有工具都是最新状态**"。

### 1.3 产品隐喻（Product Metaphor）

> **它是一个"抽屉"——不是"中控台"。**

**为什么是抽屉：**

- 🗃️ **归位感**：每个 Skill 都有自己的"格子"，打开就能找到
- 🪶 **轻量感**：抽屉默默待在那，不打扰你，但需要时永远在
- 🧹 **整理感**：整理过的抽屉让人心安，这就是产品要给用户的情绪
- 📐 **物理暗示**：推拉、归位、整齐——这些都会成为后续动效和布局的灵感来源

**反向参照（产品不是什么）：**

- ❌ 不是"**中控台**"（Control Panel）—— 太主宰、太侵入、太复杂
- ❌ 不是"**工具市场**"（Marketplace）—— 太热闹、太商业、太花哨
- ❌ 不是"**AI Copilot**"—— 我们不替用户做决策，只管"存放与分发"

## 二、目标用户（Target Persona）

### 2.1 主画像：Alex

| 属性 | 描述 |
|---|---|
| **身份** | 前端工程师 / 全栈工程师 |
| **年龄** | 28 岁 |
| **AI 工具栈** | Cursor + Claude Code + CodeBuddy（≥ 2 个同时使用） |
| **项目情况** | 同时维护 3~5 个活跃项目 |
| **技术能力** | 熟悉终端、Git、Markdown，能看懂 YAML |
| **审美水平** | 关注 Linear / Raycast / Arc / Vercel 这类有设计感的工具 |
| **使用场景** | 本地桌面为主，不依赖云端协作 |

### 2.2 Alex 的一天（痛点瞬间）

> 早上 9:00，Alex 在**项目 A** 里用 Cursor 打磨了一个新版「代码审查 Skill」，效果很好。  
> 下午 2:00，他切到**项目 B**，用 CodeBuddy 让它帮忙审查代码——发现输出质量明显下降。  
> 一查才知道：**CodeBuddy 里装的还是上周的旧版**。  
> 他叹了口气：「**又要手动复制一遍……这已经是这周第三次了。**」  
>
> 这种"**旧版本的尴尬**"每天发生好几次，成为工作流里最不起眼、但最磨人的摩擦点。

### 2.3 情绪曲线（Emotional Curve）

```
  用前                           用后
  ────────────────────────────────
  😤 烦躁      ━━━━━━━━▶      😌 安心
  🌀 迷失      ━━━━━━━━▶      🎯 掌控
  🔁 重复      ━━━━━━━━▶      ✨ 一次到位
  ❓ 不确定    ━━━━━━━━▶      ✅ 确定性
```

**设计启示**：产品要传递的核心情绪是 **"安心"和"掌控感"**，不是"兴奋"或"惊喜"。所以——

- 视觉应当**克制**，而不是华丽
- 动效应当**明确**，而不是炫技
- 文案应当**诚实**，而不是营销

## 三、核心承诺（Brand Promise）

> **让你永远用到"最新版本的自己"。**

你写的 Prompt、调的 Skill、积累的 Rule，不会因为换了 AI 助手、换了项目，就退回上个月的版本。

**新鲜度，就是信任。**

### 3.1 这句承诺如何落到产品

| 用户关心的事 | 产品的回答 |
|---|---|
| 我的 Skill 现在是最新吗？ | 首屏就告诉你"全部最新"或"3 项需更新" |
| 哪些工具的哪些项目过时了？ | 二维矩阵一眼可见，不用挨个点开 |
| 万一同步失败怎么办？ | 失败也是状态，不藏着掖着，给出重试路径 |
| 我能相信它默默在工作吗？ | 轻量无侵入，不接管你的 AI 工具，只做配置管家 |

## 四、差异化定位（Differentiation）

### 4.1 我们做什么 / 不做什么

| 我们做 | 我们不做 |
|---|---|
| ✅ **可视化** AI 工具的配置状态 | ❌ 替代 AI 工具本身 |
| ✅ **同步** 配置到多个目标 | ❌ 生成或改写你的 Prompt 内容 |
| ✅ **轻量管家** 角色，存在感低 | ❌ 成为新的"学习负担" |
| ✅ 让本地文件系统是**单一事实源**（Source of Truth） | ❌ 强制云端账号 / 订阅 |

### 4.2 相对竞品的锋利点

| 竞争场景 | 用户现有方案 | 我们的优势 |
|---|---|---|
| 手动复制粘贴 | 自己记忆 + 肉眼对比 | **可视化**状态一眼可见 |
| 自己写 symlink / shell 脚本 | 能用但脆弱、不通用 | **跨工具**统一 + 零维护成本 |
| 单个 AI 工具的插件市场 | 只服务于该工具 | **跨工具**，覆盖整个工作流 |
| 云端 Prompt 管理平台 | 绑定账号、可能侵入 | **本地优先**、**无侵入**、**无需登录** |

## 五、气质坐标（Brand Coordinates）

### 5.1 五维定位

| 维度 | 坐标 | 翻译为设计语言的初步方向 |
|---|---|---|
| **温度** | 冷静克制（Cool & Restrained） | 低饱和度配色，禁用渐变背景，不用暖黄/暖橙作为主色 |
| **气质** | 工程精准（Precise & Engineered） | 严格栅格，等宽字体承载状态/hash/路径，数字 tabular-nums |
| **亲和** | 友好专业（Friendly & Pro） | 圆角 ≥ 8px（去工程冰冷感），文案动词开头，避免术语堆砌 |
| **密度** | 留白充足（Spacious） | 间距 ≥ 16px，一屏核心信息 ≤ 7 个，绝不堆砌 |
| **年龄** | 年轻（20–30） | 现代无衬线字体、轻量动效、暗色模式一等公民 |

### 5.2 坐标系可视化

```
                      工程精准
                         │
                         │   🎯 AIToolsAssistant
                         │   （Raycast / Linear 区）
                         │
                         │   · Vercel Dashboard
         冷静 ─────────────────────── 温暖
                         │
            · Apple HIG  │   · Notion
                         │   · Figma
                         │
                      创意灵动
```

**我们所在象限**：**冷静 × 工程精准**，但通过**留白、圆角、轻动效**向"温暖"象限拉回约 20%，避免变成冷冰冰的 JIRA。

### 5.3 灵感参照系（Mood Board Anchors）

**正面参照（气质同频）**：

- **Raycast** —— 精致工具感 + 快捷操作 + 暗色优先
- **Linear** —— 极简信息密度 + 键盘友好 + 克制配色
- **Arc Browser** —— 柔和动效 + 大胆留白 + 现代感
- **Vercel Dashboard** —— 清爽仪表盘 + 状态可见 + 工程师审美

**反面参照（明确不像）**：

- **Notion** —— 太温暖太温馨，我们不要卡通插画和彩色 Emoji 堆砌
- **JIRA** —— 太工程太冰冷，没有人味
- **Adobe 系** —— 太重视觉、太花哨，不符合"管家"角色
- **钉钉 / 企业微信** —— 太 B 端、太官方，不符合个人工具调性

## 六、品牌口号体系（Voice & Tone）

### 6.1 Slogan 三档

| 使用场景 | 中文 | 英文 |
|---|---|---|
| **主口号** | 你写一次，它到处都在。 | Write once. Sync everywhere. |
| **正式描述** | 一次配置，同步到所有需要的地方。 | One config. Synced everywhere. |
| **情绪口号**（用于 Hero / 广告） | 让你永远用到最新版本的自己。 | Always the latest you. |

### 6.2 语气规范（Tone of Voice）

**对话对象**：Alex（懂技术、有审美、讨厌废话）

| 场景 | ✅ 这样写 | ❌ 不要这样写 |
|---|---|---|
| 功能按钮 | 「同步全部」 | 「立即执行同步操作」 |
| 成功反馈 | 「3 项已同步」 | 「恭喜您，同步操作已成功完成！🎉」 |
| 错误提示 | 「CodeBuddy 未连接。检查路径」 | 「很抱歉，我们遇到了一个小问题……」 |
| 空状态 | 「抽屉是空的。导入第一个 Skill 开始。」 | 「Oops！这里空空如也，快来添加吧～」 |
| 介绍 | 「管理你的 AI 配置」 | 「赋能您的 AI 工作流生产力闭环」 |

**三条铁律：**

1. **说人话**：一个句子超过 20 个字，就要问自己能不能更短。
2. **动词开头**：所有按钮、CTA 用动词开头（同步、导入、连接），不用名词堆砌。
3. **禁用情绪表情**：🎉 / ✨ / 🚀 等装饰性 Emoji 仅用于极少数庆祝场景，不要日常使用。

## 七、本层结论对下游的约束清单

**本文档会在后续各层中被严格引用。** 下表列出"L1 结论 → 对下游层的具体约束"：

| L1 结论 | 约束了 L2~L7 的什么 |
|---|---|
| 隐喻 = 抽屉 | L4 Logo 方向、L4 Empty State 插画、L5 卡片的"嵌入感"、动效的"推拉感" |
| 气质 = 冷静 + 工程精准 | L4 主色禁用高饱和度、禁用渐变背景；L4 等宽字体要独立成 token |
| 亲和 = 友好专业 | L4 圆角最小值 ≥ 8px；L5 所有按钮文案强制动词开头 |
| 密度 = 留白充足 | L4 间距基础单位 ≥ 4px（偏爱 8/16/24）；L5 一屏信息点 ≤ 7 |
| 用户 = Alex（技术 + 审美） | L3 暗色模式必须一等公民；L5 键盘友好必须纳入组件规范 |
| 承诺 = 永远最新 | L3 首页必须有"全局新鲜度"状态；L5 状态徽章是核心组件 |
| 反对"主宰" | L3 禁用"欢迎引导"等强交互弹窗；L5 禁用大尺寸 Hero 轮播 |
