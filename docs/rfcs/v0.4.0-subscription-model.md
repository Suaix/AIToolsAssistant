## 0. TL;DR（两段话讲完）

从 v0.4.0 起，**「一个资源的身份（是什么）」和「它要同步到哪里」彻底解耦**。源目录扁平化为 `~/.aitools/skills/<name>/`，不再区分 `user/` 和 `project/`。同步目标由**订阅清单**描述：全局订阅放在 `config.yaml` 的 `user_subscriptions`，项目订阅放在 `<project>/.aitools/project.yaml`。

CLI 新增 `subscribe` / `unsubscribe` 命令；`sync` 语义变为**"读订阅清单、遍历同步"**；`--skill` 参数直接移除（commander 抛「未知参数」即可）。**本 RFC 仅涵盖 CLI 侧**，GUI 如何适配订阅模型由后续 RFC-002 专门处理。本次是早期阶段的**破坏性重构，不提供迁移工具**：用户遇旧结构自行 `rm -rf ~/.aitools` 重新 `init`。

## 1. 动机（Why）

### 1.1 现有痛点

当前 v0.2/v0.3 架构存在 3 个结构性问题：

| 现象 | 根因 |
|---|---|
| 同一个 skill 从"用户级"变成"项目级"要 `mv` 文件 | 身份被物理目录绑定 |
| GUI 里只能看到"已关联到当前项目"的 project skill，`skills/project/` 下的候选池孤立 | 项目级展示依赖 cwd，而 GUI 的 cwd 不是业务项目 |
| 单卡「同步」按钮意外写入 `project.yaml` | `sync --skill` 混合了"关联到项目"和"同步"两个语义 |

三个问题的共同根因是：**v0.2.0 设计时把「用户级 vs 项目级」当成资源的属性，而它实际应该是资源的"用途关系"**。

### 1.2 产品目标对齐

- **Slogan**：「你写一次，它到处都在」——「到处」是**订阅关系的集合**，不是目录层级
- **用户画像（Alex）**：同时在多个项目间切换，经常改一个 skill 后希望立即"到处都更新"
- **抽屉隐喻**：抽屉（源）里放着所有工具；标签（订阅）告诉抽屉里每个工具要摆到哪几张桌子上

### 1.3 非目标（Out of Scope）

- 本 RFC **只涵盖 CLI 侧**。GUI 如何适配订阅模型由**后续 RFC-002** 专门起草
- 本 RFC **不提供** 从 v0.3 迁移到 v0.4 的自动化工具（早期阶段，破坏性重构）
- 本 RFC **不涉及** Skills 以外资源类型（commands/agents/rules）的业务实现——它们随 Skills 一起享受订阅模型，但各自是否进入"已实现"状态由后续 RFC 决定
- 本 RFC **不涉及** 云同步、团队共享等远期能力

## 2. 核心概念（3 个维度，正交）

```
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  1. 资源 Resource                                            │
│     定义：一个有 SKILL.md 的文件夹                            │
│     位置：<source>/skills/<name>/                           │
│     唯一标识：<type>:<name>                                  │
│                                                             │
│  2. 目标 Target                                              │
│     定义：某个 AI 工具的配置根目录                             │
│     配置：targets[].name + user_base                         │
│     衍生路径：                                                │
│       - 用户级：<user_base>/<type>/<name>/                  │
│       - 项目级：<projectDir>/.<target.name>/<type>/<name>/  │
│                                                             │
│  3. 订阅 Subscription                                        │
│     定义：把一个资源同步到一个「位置」的声明                    │
│     位置有两种：                                              │
│       - user：用户级（所有启用的 target 都接收）               │
│       - project：某个具体项目的项目级                           │
│     订阅是 N:N 关系：                                         │
│       一个资源可订阅到任意多个位置                             │
│       一个位置可有任意多个订阅                                 │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 2.1 订阅关系的表达

**全局用户级订阅**（`~/.aitools/config.yaml`）：

```yaml
source: ~/.aitools
targets:
  - { name: codebuddy,     enabled: true,  user_base: ~/.codebuddy }
  - { name: claude-code,   enabled: false, user_base: ~/.claude }

user_subscriptions:                    # 新增
  skills:
    - brand-guidelines                 # 所有已启用 target 的用户级目录都会收到
    - tdd-workflow
  commands: []                         # 预留
  agents: []
  rules: []
```

**项目级订阅**（`<project>/.aitools/project.yaml`，沿用现有字段）：

```yaml
skills:
  - brand-guidelines                   # 同步到 <project>/.codebuddy/skills/brand-guidelines/
  - frontend-design
```

### 2.2 一个资源的完整视图

假设源目录有 `brand-guidelines`，同时出现在：

- `~/.aitools/config.yaml` 的 `user_subscriptions.skills`
- `~/workspace/my-webapp/.aitools/project.yaml` 的 `skills`

同步效果（targets 都启用）：

```
源：   ~/.aitools/skills/brand-guidelines/
         ↓ 订阅 [user]            → ~/.codebuddy/skills/brand-guidelines/
         ↓ 订阅 [user]            → ~/.claude/skills/brand-guidelines/
         ↓ 订阅 [project my-webapp] → ~/workspace/my-webapp/.codebuddy/skills/brand-guidelines/
         ↓ 订阅 [project my-webapp] → ~/workspace/my-webapp/.claude-code/skills/brand-guidelines/
```

**一个订阅展开为「N 个 target」的物理目录**（N = 当前启用 target 数量）。资源视角看，就是"写一次 brand-guidelines，它到 4 个地方都在"。

## 3. 数据结构（Types）

### 3.1 配置文件

```typescript
// ~/.aitools/config.yaml
interface Config {
  source: string;
  targets: Target[];
  sync: SyncOptions;

  /** v0.4 新增：全局用户级订阅清单 */
  user_subscriptions: UserSubscriptions;
}

interface Target {
  name: string;
  enabled: boolean;
  user_base: string;
}

interface UserSubscriptions {
  skills: string[];       // 资源 dirName 数组
  commands?: string[];
  agents?: string[];
  rules?: string[];
}
```

```typescript
// <project>/.aitools/project.yaml 结构不变（v0.2/0.3 已有）
interface ProjectConfig {
  skills: string[];
  commands?: string[];
  agents?: string[];
  rules?: string[];
}
```

### 3.2 资源元数据

`ResourceInfo` 去掉 `scope` 字段（不再有 user/project 物理分层）：

```typescript
interface ResourceInfo {
  name: string;
  description: string;
  path: string;
  dirName: string;
  type: ResourceType;
  // scope 字段删除
}
```

新增"一个资源的订阅视图"类型，供 list / 未来 GUI 使用：

```typescript
/** 单个资源在某个目标的单次同步状态 */
interface SubscriptionTargetStatus {
  target: string;                        // target.name
  status: 'synced' | 'changed' | 'not_synced';
  targetPath: string;
}

/** 单个订阅位置的展开状态 */
interface SubscriptionStatus {
  /** 订阅位置类型 */
  scope: 'user' | 'project';
  /** 项目路径（scope=project 时有值） */
  projectDir?: string;
  /** 该位置下各 target 的同步状态 */
  targets: SubscriptionTargetStatus[];
}

/** 一个资源的完整视图（list 命令 + 未来 GUI 卡片用） */
interface ResourceView {
  name: string;
  dirName: string;
  description: string;
  path: string;
  sourceHash: string;
  /** 所有订阅位置 */
  subscriptions: SubscriptionStatus[];
}
```

## 4. CLI 命令设计

### 4.1 命令全表（v0.4.0 终态）

| 命令 | 作用 | 变化 |
|---|---|---|
| `aitools init` | 初始化 | 骨架从 8 个（`{skills,commands,agents,rules} × {user,project}`）改为 4 个（扁平）；完成后给出**首次订阅引导** |
| `aitools list [type]` | 列出资源 + 订阅状态 | 输出结构改为 `ResourceView[]`（见 §3.2） |
| `aitools sync [type] [name]` | 遍历订阅、同步 | 以订阅清单为唯一真相源；不再自动"智能检测项目级" |
| `aitools subscribe <type> <name> [--scope <scope>]` | 订阅一个资源 | **新命令** |
| `aitools unsubscribe <type> <name> [--scope <scope>]` | 取消订阅 | **新命令** |

**已移除**：`aitools sync --skill <name>`。传入会被 commander 视为未知参数，原生报错。

### 4.2 `aitools subscribe`（新）

```bash
# 订阅到全局用户级（写 ~/.aitools/config.yaml 的 user_subscriptions）
aitools subscribe skills brand-guidelines --scope user

# 订阅到当前项目（写 <cwd>/.aitools/project.yaml）
aitools subscribe skills brand-guidelines --scope project

# 默认 scope=user（最常见场景：把常用 skill 铺到所有 AI 工具）
aitools subscribe skills brand-guidelines

# 订阅同时立即同步（--sync 开关）
aitools subscribe skills brand-guidelines --scope project --sync
```

#### 关键行为

- **幂等**：重复订阅不报错、不重复写入
- **资源存在性校验**：`<name>` 对应的源资源不存在时报错（`aitools: 资源不存在: skills/<name>`），不创建空订阅
- **`--scope project` 且无项目配置**：
  - 若 `<cwd>/.aitools/project.yaml` 不存在，**交互式询问** `是否在当前目录创建项目配置？(y/N)` 
  - 用户选 n 或 JSON 模式下自动判 n → 报错中止
  - 用户选 y → 创建最小项目配置后继续订阅

### 4.3 `aitools unsubscribe`（新）

```bash
aitools unsubscribe skills brand-guidelines --scope user
aitools unsubscribe skills brand-guidelines --scope project

# --prune 顺便清理目标侧已同步的文件
aitools unsubscribe skills brand-guidelines --scope user --prune
```

#### 关键行为

- **幂等**：取消未订阅的资源不报错（输出 "未订阅，跳过"）
- **`--prune`**：不做二次确认（符合 §11 原则「明确先于惊喜」—— 用户主动打 `--prune`，视为已明确意图）
- **`--prune` 清理范围**：仅清理该订阅对应的目标路径（如 `--scope user` 的 prune 不会动 project 目录）

### 4.4 `aitools sync`（语义重塑）

```bash
aitools sync                     # 所有类型、所有订阅（user + 当前 cwd 项目）
aitools sync skills              # 仅 skills、所有订阅
aitools sync skills <name>       # 位置参数：只同步该资源的所有订阅
aitools sync --scope user        # 只处理 user 订阅
aitools sync --scope project     # 只处理当前 cwd 项目的订阅
aitools sync --target codebuddy  # 只同步到某个 target
```

#### 位置参数歧义处理

`aitools sync <arg>` 存在歧义：`<arg>` 可能是 type（skills）或 name（brand-guidelines）。解析规则：

1. 先尝试匹配已注册的 ResourceType（`skills/commands/agents/rules/all`）
2. 若未命中，当作 `name` 处理：在所有**已实现类型**的订阅清单中查找 → 有唯一匹配则同步那一个；多个类型都有同名 → 报错要求用户显式指定 `sync <type> <name>`

### 4.5 `aitools init` 的引导流程（调整）

init 完成后，**新增一段首次订阅引导**（非交互式，仅打印）：

```
✅ 配置已创建：~/.aitools/config.yaml
✅ 源目录骨架已生成：~/.aitools/{skills,commands,agents,rules}/

📌 下一步：
   1. 把你的 skill 文件夹放入 ~/.aitools/skills/<name>/
   2. 订阅到用户级（所有 AI 工具）：
        aitools subscribe skills <name>
   3. 查看当前状态：
        aitools list
   4. 同步：
        aitools sync
```

**不自动订阅任何资源**——订阅必须由用户显式声明（贴合 §11「明确先于惊喜」）。

## 6. 破坏性变更与升级指引

### 6.1 破坏性变更清单

| 变更 | 影响 |
|---|---|
| 源目录扁平化（去掉 `user/` 和 `project/` 子层） | 旧结构的 skill 文件夹不会被 v0.4 识别 |
| `config.yaml` 新增必需字段 `user_subscriptions` | 旧配置缺字段，`loadConfig()` 直接报错 |
| `sync --skill` 参数移除 | 旧脚本调用会报「未知参数」 |
| `ResourceInfo.scope` 字段删除 | 内部 API 破坏，不影响用户 |
| list / sync 的 JSON 输出结构变化 | 桌面 App v0.3 会读取失败（由 RFC-002 负责 GUI 适配） |
| 项目级"智能检测"逻辑移除 | `aitools sync` 不再依据 `<cwd>/.codebuddy/` 存在性自动检测；必须显式订阅 |

### 6.2 升级指引（给使用 v0.3 的用户）

> ⚠️ 本版本不提供自动迁移工具。项目处于早期开发阶段，用户自行重建源目录即可。

```bash
# 1. 备份现有 skill 内容（可选）
cp -r ~/.aitools ~/.aitools.bak

# 2. 清空旧结构
rm -rf ~/.aitools

# 3. 重新初始化（生成新扁平结构 + 新 config.yaml）
aitools init

# 4. 把备份里的 skill 文件夹搬进新目录（手动）
cp -r ~/.aitools.bak/skills/user/* ~/.aitools/skills/
cp -r ~/.aitools.bak/skills/project/* ~/.aitools/skills/

# 5. 显式订阅到用户级
aitools subscribe skills brand-guidelines
aitools subscribe skills tdd-workflow
# ... 按需逐个订阅

# 6. 在业务项目目录下订阅项目级
cd ~/workspace/my-webapp
aitools subscribe skills brand-guidelines --scope project --sync

# 7. 确认无问题后删除备份
rm -rf ~/.aitools.bak
```

### 6.3 版本号

0.3.x → **0.4.0**（主版本号不动，minor 升级体现破坏性——项目 < 1.0，semver 规则放宽）。

## 7. 核心流程（关键场景图）

### 7.1 场景 F1：用户改一次 skill，全部订阅者更新

```
用户编辑 ~/.aitools/skills/brand-guidelines/SKILL.md
                        │
                        ▼
         aitools sync skills brand-guidelines
                        │
                        ▼
         读取 config.yaml.user_subscriptions.skills → 含 brand-guidelines

                        │

                        └── 项目级订阅：复制到 <cwd>/.codebuddy/skills/, <cwd>/.claude-code/skills/
                        │
                        ▼
                  输出 summary
```

### 7.2 场景 F2：用户给新项目快速配置 skill

```
cd ~/workspace/new-project
           │
           ▼
         aitools subscribe skills brand-guidelines --scope project --sync
           │
           ├── 检测到 .aitools/project.yaml 不存在 → 询问 y/N
           │    用户选 y
           │
           ▼
         创建 new-project/.aitools/project.yaml
         写入 skills: [brand-guidelines]
         复制 brand-guidelines 到 new-project/.{codebuddy,claude-code}/skills/
```

### 7.3 场景 F3：取消订阅 + 清理目标

```
         aitools unsubscribe skills old-skill --scope user --prune
                        │
                        ▼
         从 config.yaml.user_subscriptions.skills 删除 old-skill
         删除 ~/.codebuddy/skills/old-skill/
         删除 ~/.claude/skills/old-skill/
         （项目级订阅不受影响，若有）
```

### 附：GUI 适配的占位说明

v0.4 发布后，桌面 App v0.3 会立即报错（JSON 结构变化 + 配置结构变化）。处理方式：

- **短期**：桌面 App 仅显示「CLI 版本不兼容，请参考 RFC-002 升级 GUI」的提示
- **长期**：RFC-002 单独起草，规划项目选择器、订阅开关、卡片订阅视图等 GUI 新交互

**本 RFC 不为 GUI 做任何代码工作。**

## 9. 风险

| 风险 | 严重度 | 缓解 |
|---|---|---|
| 用户误删 `skills/<name>/` 导致订阅孤儿 | 🟡 中 | sync 时遇到订阅但源缺失 → warn，不中断；list 标记"源已删除" |
| `sync skills <name>` 位置参数歧义 | 🟢 低 | §4.4 已定义消歧规则 + 单测覆盖 |
| `--prune` 不二次确认 → 误删 | 🟢 低 | 符合"明确先于惊喜"；用户主动打参数视为明确意图 |
| v0.4 发布后 v0.3 GUI 立即失效 | 🟡 中 | 本 RFC §8 附注明确告知；RFC-002 承接 GUI 适配 |

## 10. 设计原则自查（对齐 L2）

| 原则 | 本 RFC 的体现 |
|---|---|
| **诚实先于友好** | 破坏性变更 README 明确列出；sync 遇孤儿订阅 warn 但不中断；不提供 silent 迁移 |
| **状态先于功能** | list 输出以"订阅状态"为视觉中心；init 完成后给出明确下一步清单 |
| **明确先于惊喜** | 订阅必须显式声明；init 不自动订阅；`--prune` 不二次确认；`--skill` 不做 deprecation 转发，让 commander 直接报错 |
| **克制先于全面** | 不引入"group"、"tag"、"workspace" 等抽象；不做迁移工具；不管 GUI 适配 |

## 11. 附录

### 11.1 术语表

| 术语 | 英文 | 定义 |
|---|---|---|
| 资源 | Resource | 一个有主文件（如 SKILL.md）的文件夹 |
| 目标 | Target | 一个 AI 工具的配置根（如 CodeBuddy） |
| 订阅 | Subscription | "把资源同步到某位置"的声明 |
| 位置 | Location | 订阅的落点：user（全局用户级）或 project（某具体项目） |
| 源 hash | Source Hash | 资源文件夹的 SHA-256 全量 hash，用于变更检测 |
| 孤儿订阅 | Orphan Subscription | 订阅存在但源资源已删除的情况 |

### 11.2 与其他系统的设计参考

| 系统 | 参考点 |
|---|---|
| **Git branch / remote** | 同一个提交可被多个 branch/remote 引用，身份不绑定物理位置 |
| **npm workspaces** | 一个包可被多个 workspace 依赖，依赖关系在 manifest 里显式声明 |
| **Spotify 歌单** | 一首歌可在多个歌单里出现，歌本身只有一份 |
