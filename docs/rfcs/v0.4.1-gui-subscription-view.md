## 0. TL;DR（三段话讲完）

**第一段 · 现状**：CLI v0.4 已经把订阅模型落地（`subscribe`/`unsubscribe` 命令、`list` 输出 `ResourceView[]`），但 `desktop/src/` 的所有代码还活在 v0.3：类型定义 `ResourceListItem` 仍带 `scope` 字段、Skills 页用已删除的 `sync --skill` 参数、Dashboard 依赖早已不存在的 `userResources/projectResources` 双段事件。**GUI 当前直接跑会解析失败**。

**第二段 · 方向**：GUI 升级为订阅模型的视觉前端——所有订阅读写统一走 `invoke_cli` 调 `aitools subscribe/unsubscribe --json`（UI-over-CLI 契约不破），列表按"候选池 / 已订阅"二分展示，**用户级订阅和项目级订阅由顶部 Tab 切换**，Dashboard HeroCard 改为订阅驱动的三数字（订阅总数 / 候选数 / 需同步数），新增**首次启动订阅引导向导**和**项目切换器**（GUI 首次获得"当前项目"概念）。

**第三段 · 边界**：本 RFC 范围是 Skills 页 + Dashboard + Tools 页 + Settings 页补订阅字段 + 新增的 Onboarding 与 Project Switcher。**不动 CLI**（CLI 已稳定）；**不做云同步**、不做团队共享；**不做 commands/agents/rules 的 GUI 实体**——这三类资源在 CLI 侧本就是占位（handler.implemented=false），GUI 只在侧栏保留入口但显示"即将推出"。

## 1. 动机（Why）

### 1.1 直接问题：GUI 跑不起来

| 症状 | 根因（文件 / 行） |
|---|---|
| `list` 返回后 `useSkillsData` 崩溃 | `desktop/src/lib/cli.ts` 的 `ResourceListItem` 仍是 v0.3 形态，解析 v0.4 `ResourceView.subscriptions` 时读不到字段 |
| 点击 Skill 卡片"同步"按钮 CLI 报错 | `Skills.tsx` 第 294 行 `buildSyncArgs` 仍用 `--skill <name>`，v0.4 已删除该参数 |
| Dashboard 首屏空白 | Dashboard 消费 `result.userResources / projectResources`，v0.4 list 只输出单段 `ResourceView[]` |

→ **不升级 = GUI 彻底不可用**。这不是锦上添花，是回归修复 + 功能补完的混合任务。

### 1.2 产品层面：GUI 没有"订阅"这个核心概念

CLI 已经用订阅模型把"身份"和"用途"解耦了，但 GUI 目前只在展示"身份"（Skill 的名字 / 描述 / 路径）。用户在 GUI 里**无法回答 3 个关键问题**：

1. 我有哪些 skill 没订阅，只是躺在 `~/.aitools/skills/` 里？
2. 我当前的项目订阅了哪些 skill？
3. 我在哪里点击能把一个 skill 从"用户级"改成"项目级"？

这三个问题不解决，GUI 就永远只是"文件夹查看器"而不是"AI 工具同步管家"。

### 1.3 对齐设计系统（L2 原则）

- **状态先于功能**：首屏 HeroCard 必须先告诉用户"有 N 个资源待同步"，而不是先给一堆按钮
- **明确先于惊喜**：订阅 scope 必须显式（Tab 切换 + 订阅操作时写清"订阅到用户级"），不能让用户"点下去才发现改了项目配置"
- **克制先于全面**：不做"云同步"、不做"团队共享"、不做"Skill 编辑器"——这三个都不在 RFC-001 承诺范围内

### 1.4 非目标（Out of Scope）

- ❌ 不做云同步 / 团队共享
- ❌ 不做 GUI 内的 Skill 编辑器（用户继续用 IDE 编辑源文件）
- ❌ 不做 commands/agents/rules 的业务实现——等它们在 CLI 侧 `implemented=true` 后再有独立 RFC
- ❌ 不做多项目并排视图——当前只支持"看一个项目"，项目切换器一次切换一个
- ❌ 不做订阅的批量操作（多选 → 批量订阅）——首版单条操作

## 2. 核心概念映射（CLI ↔ GUI）

GUI 不定义新概念，只决定"CLI 的概念怎么出现在界面里"。

| CLI 概念（RFC-001） | GUI 呈现 | 所在页面 |
|---|---|---|
| `ResourceView` | Skill 卡片 | Skills 页 |
| `ResourceView.subscriptions[]` 为空 | 卡片分类到"候选"区 | Skills 页候选段 |
| `ResourceView.subscriptions[scope=user]` | User Tab 可见 | Skills 页 User Tab |
| `ResourceView.subscriptions[scope=project]` | Project Tab 可见，且卡片带项目路径标签 | Skills 页 Project Tab |
| `SubscriptionTargetStatus.status='drift'` | 卡片右上角黄色小圆点 + "需同步" | Skills 卡片、Dashboard |
| `subscribe` 事件流 | 订阅按钮点击后 toast + 列表动画重排 | Skills 页、Onboarding 向导 |
| 项目配置 `<cwd>/.aitools/project.yaml` | 顶部项目切换器下拉 | 全局 |
| `guideFirstSubscription` 引导文案 | 首次启动向导 3 步 | Onboarding 蒙层 |

**关键原则**：GUI 不再在前端做"scope 推断"——所有 scope 决策都带入 CLI 调用参数，CLI 返回什么 GUI 就显示什么。

## 3. 信息架构（L3 对齐）

### 3.1 侧栏（Sidebar）—— 微调

现状：Dashboard / Skills / Tools / Settings（4 项）

新版：**保持 4 项不变**，但 Skills 图标旁增加订阅计数徽章（例：`Skills 12`），对应 User + Project 订阅总数。Tools 图标旁增加 target 启用数（例：`Tools 3/4`）。

**不增加** commands/agents/rules 的侧栏入口——它们还没 implemented，避免空页误导用户。

### 3.2 顶栏（新增）—— 项目切换器

```
┌──────────────────────────────────────────────────────┐
│ aitools   │  📁 ~/workspace/aiproject/AIToolsAssistant ▼ │
└──────────────────────────────────────────────────────┘
```

**行为**：
- 下拉展开后列出"最近打开的项目"（GUI 内存+持久化到 `~/.aitools/gui-state.json`）
- 顶部有"打开其他目录…"按钮 → 调用 Tauri `dialog.open({ directory: true })`
- 选中的项目会持久化到 GUI 本地状态，作为所有 `invoke_cli` 调用的 `cwd` 参数
- 若当前目录无 `.aitools/project.yaml`，切换器显示"📁 目录名（未初始化）"，Project Tab 显示空态引导"在此目录创建项目配置"按钮

### 3.3 页面内分段 —— Skills 页重构

```
┌─ Skills ──────────────────────────────────────────────┐
│                                                       │
│ [User Subscriptions] [Project Subscriptions] [Unused] │  ← 三段 Tab
│                                                       │
│ ┌─ Skill 卡片 ─────────────────────────────────────┐  │
│ │ brand-guidelines               [Synced ✓]       │  │
│ │ 品牌指南 skill                                   │  │
│ │ user • 3 targets • 无 drift                     │  │
│ │ [打开源文件] [取消订阅]                          │  │
│ └──────────────────────────────────────────────────┘  │
│                                                       │
└───────────────────────────────────────────────────────┘
```

**三段 Tab 的归类规则**（来自 `ResourceView.subscriptions`）：

| Tab | 进入条件 |
|---|---|
| **User Subscriptions** | 至少有一个 `subscriptions[scope=user]` |
| **Project Subscriptions** | 至少有一个 `subscriptions[scope=project, projectDir=当前切换器选中项目]` |
| **Unused** | 源里存在、但无任何订阅（或只有其他项目的订阅） |

**同一资源可能在多个 Tab 都出现**（它既订到了用户级又订到了当前项目），这是正确的——用户看到的是"订阅关系"而非"资源身份"。

### 3.4 Dashboard 重构

```
┌─ Dashboard ───────────────────────────────────────────┐
│                                                       │
│  HeroCard（状态先于功能）                               │
│  ┌─────────────────────────────────────────────────┐  │
│  │  你写一次，它到处都在                             │  │
│  │                                                 │  │
│  │  12 个订阅 · 5 个候选 · 2 个需同步               │  │
│  │  [一键同步全部] [查看详情 →]                     │  │
│  └─────────────────────────────────────────────────┘  │
│                                                       │
│  RecentActivity（最近一次 sync 的事件流）              │
│                                                       │
└───────────────────────────────────────────────────────┘
```

HeroCard 五种状态（延续现有 L5 规范）：

| 状态 | 触发 | 主按钮文案 |
|---|---|---|
| `empty` | `subscribeCount=0 && candidateCount=0` | 开始订阅 |
| `no-subscription` | `subscribeCount=0 && candidateCount>0` | 订阅第一个 skill |
| `synced` | `subscribeCount>0 && driftCount=0` | 查看详情 |
| `drift` | `driftCount>0` | 一键同步全部 |
| `error` | 上一次 sync 有 `failed>0` | 查看错误 |

## 4. 新增功能模块

### 4.1 首次启动向导（Onboarding Wizard）

**触发条件**：GUI 启动时读到 `~/.aitools/config.yaml` 的 `user_subscriptions` 为空且源目录有 ≥1 个候选资源 → 显示蒙层向导（不是强制，右上角可关闭）。

**3 步流程**：

```
Step 1/3 · 你有这些 AI 工具被识别到
  ☑ codebuddy   启用
  ☑ claude      启用
  ☐ cursor      未识别（跳过）
  [继续]

Step 2/3 · 源目录里的 skill
  发现 5 个 skill：
    ☑ brand-guidelines
    ☑ frontend-design
    ☐ pdf
    ☐ xlsx
    ☐ pptx
  勾选的会被订阅到 User 级（所有工具）
  [继续]

Step 3/3 · 确认并同步
  将订阅 2 个 skill 到用户级
  并立即同步到 2 个工具 = 4 个写操作
  [确认，开始同步]
```

**实现**：Step 3 的"确认"本质上是一串 `aitools subscribe skills <name> --scope user --sync --json` 串行调用 + NDJSON 事件流实时刷新进度条。**不引入新的 CLI 命令**。

### 4.2 项目切换器

见 §3.2。关键交互：
- 切换项目 = 切换后所有 `invoke_cli` 带新的 `cwd`
- 切换时如果 Skills 页正在加载，先 abort 旧请求再发新请求（Tauri 端已有 AbortController 支持）
- 持久化到 `~/.aitools/gui-state.json`（本 RFC 不定义该文件结构细节，由实施阶段决定）

### 4.3 订阅/取消订阅交互

**订阅按钮**（Unused Tab 的卡片）：
```
点击 [订阅] → Popover: 
  订阅到哪里？
    ○ 用户级（所有工具都接收）
    ○ 项目级（仅 <当前项目名>）
  [ ] 订阅后立即同步
  [确认] [取消]
```

→ 生成命令：`aitools subscribe skills brand-guidelines --scope <user|project> [--sync] --json`（带当前 `cwd`）

**取消订阅按钮**（User/Project Tab 的卡片）：
```
点击 [取消订阅] → 直接确认对话框:
  取消订阅"brand-guidelines"（用户级）？
  [ ] 同时从工具目录中删除已同步的文件（--prune）
  [确认] [取消]
```

→ 生成命令：`aitools unsubscribe skills brand-guidelines --scope <scope> [--prune] --json`

**原则遵守**：
- 所有写操作走 CLI（不前端直接改 yaml）✅ UI-over-CLI
- `--prune` 必须用户显式勾选，不默认 ✅ 明确先于惊喜
- 订阅操作完成后**不自动跳转 Tab**，只在当前 Tab 内刷新并给出 toast"已订阅到项目级，见 Project Tab"——让用户自己决定是否跳过去看 ✅ 克制

## 7. 关键决议（Resolved Questions）

以下 4 个问题在 2026-04-28 定稿时已敲定。保留原问题陈述便于后人理解"为什么这样选"。

---

**Q1 · Tools 页怎么改 target 启用状态？** → ✅ **方案 B**

原问题：CLI 没有 `aitools target enable/disable` 命令，GUI 要开启/关闭一个 target 要么直写 yaml（违反 UI-over-CLI），要么推 CLI 新增命令（扩大本 RFC 范围）。

**决议**：由 **RFC-001.1 patch**（单独起草的小 RFC / 或直接 patch 本系列）给 CLI 补两个命令：

```bash
aitools target enable <name>    # 将 targets[?name==name].enabled 置为 true
aitools target disable <name>   # 置为 false
```

- 两命令幂等，输出 NDJSON 事件 `target.enabled` / `target.disabled`
- 实施顺序：**RFC-001.1 必须在阶段 3 开工前合入**；若未合入，阶段 3 的 Tools 页启用开关临时只读（tooltip："请手动编辑 ~/.aitools/config.yaml"），不阻塞阶段 3 的其他内容
- **本 RFC 不承担** RFC-001.1 的实施工作，只承担其消费

---

**Q2 · 当前项目"未初始化"时的 Project Tab 是什么？** → ✅ **方案 A**

原问题：切换器选中一个没有 `.aitools/project.yaml` 的目录时，Project Tab 该显示什么？

**决议**：显示**空态 + 主按钮"在此目录创建项目配置"**。点击后的行为：

- GUI 直接弹 "订阅到项目" Popover（见 §4.3），用户选中一个 skill 后走 `aitools subscribe skills <name> --scope project --json`
- CLI 自带的"询问创建 project.yaml"逻辑在 JSON 模式下默认判 No，所以 GUI 要在 Popover 里**显式提示**：「首次订阅会在当前目录创建 `.aitools/project.yaml`」并让用户勾选确认
- 如果用户选择"只想创建空项目，暂不订阅"：提供一个辅助入口"仅创建项目配置"，调用 `aitools subscribe skills __placeholder__ --scope project --json`（利用 CLI 的资源校验失败路径）——**不，这个做法不优雅**
- 替代方案：**阶段 4 实施时若发现需要"只创建不订阅"入口，由 RFC-001.1 patch 附带加一个 `aitools project init` 命令**。首版按"必须伴随一次订阅才能创建 project.yaml"执行，与 CLI 当前行为保持一致

**理由**：贴合 L2 原则「状态先于功能」——告诉用户"当前状态是未初始化"比把 Tab 灰掉更有信息量。

---

**Q3 · `sourceHash` 是否需要在 GUI 展示？** → ✅ **不展示**

原问题：展示短哈希（前 7 位）能帮 debug，但会增加视觉噪音。

**决议**：首版**不展示**。drift 判定由 CLI 在 list 输出里给出 `SubscriptionTargetStatus.status` 字段，GUI 只渲染状态文字（"同步中" / "需同步" / "有冲突"）和小圆点即可。

后续若出现"用户想自己核对 hash"的需求，等 Skill 详情页（本 RFC 不设计）落地时再加。

---

**Q4 · Onboarding 向导对"所有 target 都未安装"的用户显示什么？** → ✅ **方案 A（精细化）**

原问题：用户连 codebuddy/claude 都没装时，Step 1 全是"未识别"，向导没价值。

**决议**：Onboarding Step 1 挂载前先做判断：

```
detected_ratio = targets.filter(t => t.detected).length / targets.length
```

- `detected_ratio >= 0.3`（至少 30% 的 target 被识别到）→ 正常走 3 步向导
- `detected_ratio < 0.3` → 替换为"请先安装 AI 工具"引导页：
  - 展示所有支持的 target 清单 + 各自的"如何安装"链接（复用 `docs/design-system/components.css` 的 `.empty-state` 样式）
  - 底部按钮：「我装好了，重新检测」→ 重新运行 `aitools list --json` 拉一次
  - 右上角「我知道了，先不用」→ 关闭蒙层，并在 `gui-state.json` 里记录"下次不再弹"（避免打扰折腾中的用户）

**阈值选择理由**：30% 比草稿里的 70% 更宽松——只要有 3 个工具中的 1 个被装上，就让用户走正常引导；这样不会因为用户没装齐所有工具就被挡在门外。

## 8. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| CLI v0.4 输出格式后续微调 | GUI 再次崩溃 | 在 `cli.ts` 加 zod schema 校验，格式不符时降级为"请升级 CLI"提示而非崩溃 |
| `invoke_cli` 并发导致订阅操作竞态（用户快速点多次） | 订阅清单写入冲突 | 所有写操作串行化：GUI 维护一个操作队列，上一个未返回前按钮 disabled |
| 项目切换器记忆的项目目录已删除 | 启动时 `cwd` 无效 | 启动时校验 `gui-state.json` 里的项目路径是否存在，不存在则清空并 fallback 到 `$HOME` |
| Onboarding 订阅阶段中途失败 | 部分订阅成功部分失败，用户困惑 | 事件流实时显示每条结果；全部完成后给出"2 成功 1 失败"摘要 + 重试入口 |
