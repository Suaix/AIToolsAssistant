## 零、关键架构决策（Key Architectural Decisions）

**在画任何东西之前，先记录 4 条决定产品形态的关键决策。** 这些决策是 L4~L6 不能动摇的前提。

### KD-01 · 产品形态：菜单栏常驻 + 主窗口

| | 形态 A：菜单栏 Popover | 形态 B：主窗口 |
|---|---|---|
| **触发** | 点击菜单栏图标 | 从 Popover 展开 / Dock 图标 |
| **使用占比** | 约 80% | 约 20% |
| **典型任务** | 看状态、一键同步、快速查找 | 新增 Skill、配置详情、设置 |
| **尺寸** | 固定 400 × 560 px | 960 × 720 px（可缩放） |
| **技术栈建议** | 同一套 React 组件 + 不同 Shell | — |

> 📌 **为什么双形态**：Alex 每天打开关闭 3~5 次，主窗口太重；但深度操作（看内容、改配置）又需要更大画布。双形态让"轻任务极轻、重任务有空间"。

### KD-02 · 菜单栏图标的状态色点

菜单栏图标本身承担"全局新鲜度"信号：

```
🟢 绿点（无点也可）  → 全部最新（默认状态）
🟡 黄点（右下角）    → 有 N 个需更新
🔴 红点（右下角）    → 有同步失败 / 工具未连接
⚙️ 灰点（转动）      → 同步进行中
```

这是**原则 1「状态先于功能」的极致体现**——甚至不用打开 App 就知道现状。

### KD-03 · 导航模型：对象导向（Object-oriented）

**侧栏所有分组都围绕"对象"命名，而非"操作"命名。**

- ✅ Skills / Agents / 已连接工具 / 项目
- ❌ 导入 / 同步 / 管理（操作导向，违反原则 1）

### KD-04 · 单一事实源（Single Source of Truth）

整个产品只有**一个数据源**：本地 `~/.aitools/` 目录。

- 所有 UI 都是对这个目录的**投影**
- 所有操作最终都是对这个目录的**读写**
- 不做云端备份、不做账号系统、不做协作同步（贯彻原则 4）

## 一、对象模型（Domain Model）

### 1.1 核心对象

```
┌──────────────────────────────────────────────────────────────┐
│                                                              │
│                   Source（源）                                │
│                   ~/.aitools/                                 │
│                   ↑ 单一事实源                                 │
│                                                              │
│         ┌────────────────┴────────────────┐                  │
│         │                                 │                  │
│         ▼                                 ▼                  │
│  ┌──────────────┐                 ┌──────────────┐          │
│  │  Resource    │                 │   Scope      │          │
│  │  类型        │   × 组合 =      │   作用域     │          │
│  │ ┌──────────┐ │                 │ ┌──────────┐ │          │
│  │ │ Skill ⭐ │ │                 │ │ User     │ │          │
│  │ │ Command  │ │                 │ │ Project  │ │          │
│  │ │ Agent    │ │                 │ └──────────┘ │          │
│  │ │ Rule     │ │                 └──────────────┘          │
│  │ └──────────┘ │                                           │
│  └──────┬───────┘                                           │
│         │                                                   │
│         │ 同步到                                             │
│         ▼                                                   │
│  ┌──────────────┐         ┌──────────────┐                 │
│  │ Target Tool  │◆─────◆ │  Project     │                 │
│  │ (已连接工具)  │         │  (项目)      │                 │
│  │ CodeBuddy    │         │ my-web-app   │                 │
│  │ Claude Code  │         │ my-cli-tool  │                 │
│  └──────────────┘         └──────────────┘                 │
│                                                              │
└──────────────────────────────────────────────────────────────┘

⭐ = 首版主攻对象
```

### 1.2 对象的三维属性

每个 Resource（如 Skill）都有 3 个正交属性：

| 维度 | 取值 | 对 UI 的含义 |
|---|---|---|
| **类型** | Skill / Command / Agent / Rule | 决定侧栏分组 |
| **作用域** | User（全局）/ Project（项目级） | 决定"同步到哪里" |
| **同步状态** | 已同步 / 需更新 / 未同步 / 失败 | 决定视觉色调 |

**UI 设计最大的挑战**：把这个三维概念用二维界面表达清楚而不让用户懵。**解法**：侧栏承载"类型"维度，主内容区用"状态"着色，详情页展示"作用域"。

## 二、导航架构（Navigation Architecture）

### 2.1 侧栏结构（主窗口模式）

```
┌─────────────────────────────────────────┐
│  [A] aitools           [🌗 切换主题]     │  ← 顶部品牌区（64px 高）
├─────────────────────────────────────────┤
│                                         │
│  🏠  工作台                              │  ← 分组 1：状态总览
│                                         │
├─────────────────────────────────────────┤
│                                         │
│  📦  Skills               · 12          │  ← 分组 2：资源（对象导向）
│  ⚡  Commands             · —           │    · 数字 = 已管理数量
│  🤖  Agents               · —           │    · —  = 未实现（原则 3 诚实）
│  📜  Rules                · —           │
│                                         │
├─────────────────────────────────────────┤
│                                         │
│  🔗  已连接工具           · 2           │  ← 分组 3：外部关系
│  📂  项目                 · 3           │
│                                         │
├─────────────────────────────────────────┤
│  ⚙️  设置                                │  ← 底部固定
└─────────────────────────────────────────┘
```

**设计决策：**

| 决策 | 依据 |
|---|---|
| 分组之间用分割线（而不是空行） | 强化"抽屉格子"隐喻 |
| 未实现项保留占位但显示 `—` | 原则 3「诚实」：不藏也不骗 |
| 未实现项可点击，进入后显示"该版本暂未支持"空状态 | 原则 3：比"灰色禁用"更诚实 |
| 没有「搜索」独立项 | 全局搜索用 `Cmd+K` 快捷键唤起（Alex 的习惯） |
| 没有「新手引导 / 帮助」 | 原则 4「克制」：Alex 不需要 |

### 2.2 Popover 结构（菜单栏模式）

```
┌───────────────────────────────────────┐
│                                       │
│   全部最新                              │  ← Hero 状态区
│   3 个工具 · 12 个 Skill · 刚刚同步    │    （整个 Popover 最醒目）
│                                       │
├───────────────────────────────────────┤
│                                       │
│   🔍 搜索 Skill...            ⌘K     │  ← 快速搜索
│                                       │
├───────────────────────────────────────┤
│   最近同步                             │  ← 最近活动（≤ 3 条）
│   ✓ code-review    · 2 分钟前         │
│   ✓ git-workflow   · 10 分钟前        │
├───────────────────────────────────────┤
│                                       │
│   [⟳ 同步全部]    [↗ 打开完整窗口]    │  ← 底部操作区
│                                       │
└───────────────────────────────────────┘
```

**尺寸**：400 × 560 px（固定）  
**触发**：点击菜单栏图标  
**隐藏**：失焦自动隐藏 / Esc 关闭

## 三、页面清单（Page Inventory）

严格遵循原则 4 「克制」，**首版只做 5 个页面 + 2 个关键弹层**：

| # | 页面 | URL | 入口 | 核心任务 |
|---|---|---|---|---|
| P1 | **工作台** | `/` | 侧栏首项 / Popover「打开完整窗口」 | 看全局状态、最近同步、快速入口 |
| P2 | **Skills 列表** | `/skills` | 侧栏 Skills / 工作台「管理 Skills」 | 看所有 Skill 的同步矩阵 |
| P3 | **Skill 详情** | `/skills/:name` | Skills 列表卡片点击 | 看 SKILL.md 内容 + 同步目标 + 操作 |
| P4 | **已连接工具** | `/tools` | 侧栏 已连接工具 | 看 CodeBuddy / Claude Code 状态 |
| P5 | **设置** | `/settings` | 侧栏底部 | 源目录、主题、版本 |
| M1 | **同步 Modal** | — | 任何"同步"按钮 | 确认 + 进度 + 结果 |
| M2 | **导入 Skill Modal** | — | 列表页「+」/ 空态 CTA | 引导选文件夹、命名 |

**暂不做的页面**（全部违反原则 4 或范围外）：

- ❌ 项目详情页（信息放在 Skill 详情的"同步目标"区够用）
- ❌ Commands / Agents / Rules 页面（CLI 还未实现，UI 不能做期货）
- ❌ 全局搜索页（用 Cmd+K Spotlight 式弹层代替）
- ❌ 用户中心 / 账号（本地优先，无账号）
- ❌ 帮助 / 文档页（外链到 README）
- ❌ 同步历史独立页（放在工作台和详情页内即可）

## 六、Cmd+K 全局搜索（Spotlight 式）

考虑到 Alex 是技术用户 + 符合 L1 气质坐标（Raycast 参照），**全局搜索不做独立页，而做 Spotlight 式弹层**。

```
            ┌─────────────────────────────────────┐
            │  🔍 搜索 Skill、工具、设置...         │
            ├─────────────────────────────────────┤
            │                                     │
            │  最近                                │
            │    📦 code-review                   │
            │    📦 git-workflow                  │
```

**触发**：全局快捷键 `Cmd+K`  
**尺寸**：480 × 400 px  
**首版可选**：如果工期紧可后置到 v0.3，但产品气质决定了它最终一定要有

## 七、响应式与边界条件

### 7.1 窗口尺寸

| 模式 | 尺寸 | 说明 |
|---|---|---|
| Popover（菜单栏） | 400 × 560 px（固定） | 不可缩放 |
| 主窗口（最小） | 800 × 600 px | 保证侧栏 + 主内容区可用 |
| 主窗口（默认） | 960 × 720 px | 首次打开的默认尺寸 |
| 主窗口（最大） | 无限制 | 支持全屏 |

### 7.2 侧栏折叠

当窗口宽度 < 900px 时，侧栏自动收起为**图标模式**（仅显示图标，宽 64px），Hover 弹出文字提示。

### 7.3 空状态

所有列表页都必须定义空态（贯彻原则 1，不能让用户看到"空白"）：

| 场景 | 标题 | 说明 | CTA |
|---|---|---|---|
| 首次打开，没有任何 Skill | 抽屉是空的 | 导入第一个 Skill 开始。 | [+ 导入文件夹] |
| 搜索无结果 | 没有找到 | 换个关键词试试。 | — |
| 某个 Tab 未实现 | Commands 还未开放 | 该资源类型将在后续版本支持。 | 订阅更新 |
| 未连接任何工具 | 还没连接 AI 工具 | 连接后，Skill 会同步到那里。 | [+ 连接 CodeBuddy] |

## 八、本层结论对下游的约束清单

| L3 结论 | 约束了 L4~L7 的什么 |
|---|---|
| 双形态（Popover + 主窗口） | L4 必须定义两套栅格；L6 原型必须做两个入口 |
| 菜单栏图标色点 | L4 必须定义 4 种状态色（绿/黄/红/灰转动） |
| 对象导向导航 | L5 侧栏组件的分组结构固化；不允许为"操作"单独开栏 |
| 5 个核心页面 | L6 原型交付 5 个页面 + 2 个 Modal，不多不少 |
| Flow 2 的"资源滑向工具"动效 | L4 必须在 Motion Token 中单独定义一档"同步动效"（400-800ms） |
| Cmd+K 全局搜索 | L5 必须定义 Command Palette 组件 |
| 未实现项显示 `—` | L4 必须有"占位/禁用"状态的视觉规范 |
