## 1. 背景

v0.4.2 之前，仓库中 Claude 工具的标识符存在三处不一致：

| 位置 | name | user_base |
|---|---|---|
| `src/config/manager.ts:getDefaultTargets` | `claude-code` | `~/.claude` |
| `src/commands/target.ts:AVAILABLE_TOOLS` | `claude-internal` | `~/.claude-internal` |
| `desktop/src/lib/tools.ts:AVAILABLE_TOOLS` | `claude-internal` | `~/.claude-internal` |

加上 `desktop/src/lib/tools.ts:TOOL_PROJECT_DIR_ALIASES` 的双名兼容映射，
事实上有四套语义混在一起。同时 `Config` / `ProjectConfig` 缺乏 schema 版本字段，
v0.2.0 / v0.4.0 的 schema 变更只能通过抛错让用户重建 `~/.aitools/`。

## 2. 决策

### 2.1 Claude 工具规范名

采用 **`claude-internal` + `~/.claude-internal/`**，原因：
- Claude Code 官方 CLI 已占用 `~/.claude/`，aitools 应避开冲突
- GUI 与 CLI `target add` 现状均使用此名，改动面更小

### 2.2 引入配置自动迁移

撤销 v0.4.0 RFC §6.2「不提供迁移工具」的立场。新增 schema 版本感知的迁移管线
（`read → migrate → validate → normalize`），位于 `src/config/migrations/`。

支持迁移版本：v0.2.0 / v0.4.0 / v0.4.x（含 `claude-code` 旧名）→ v0.5.0。

### 2.3 引入 AI 工具元数据 SSOT

仓库根新增 `shared/tools.json` + `shared/tools.schema.ts` 作为 CLI 与 GUI 的
共享数据契约。删除 5 处分散的硬编码工具列表 / 显示名 / 别名映射。

### 2.4 目录创建边界守卫（US-6）

aitools 不再主动 mkdir AI 工具家目录（`~/.codebuddy/` / `~/.claude-internal/`
/ `<project>/.codebuddy/` 等）。`syncResourceToDir` 入口断言父目录存在，
不存在时返回 `skipped_missing_tool` action，CLI 与 GUI 均明确展示「未检测到工具」。

## 3. 关键设计选择

| 编号 | 决策 | 理由 |
|---|---|---|
| TD-1 | SSOT 用 JSON 而非 TS 模块 | CLI 与 desktop 是独立 npm 包；JSON 规避跨包 import；Rust 端未来可 `include_str!` |
| TD-3 | 迁移嵌入 `loadConfig`，无独立 `aitools migrate` 子命令 | 透明化是核心目标 |
| TD-4 | 迁移结果通过 reporter 协议解耦 | CLI/GUI 双消费方需要不同表达；测试可注入 NoopReporter |
| TD-7 | yaml 中 `version` 字段排首行 | 便于人眼自查 |
| TD-9 | 资源冲突阻断而非自动覆盖 | 用户磁盘内容不能被 aitools 单方决策（L2「诚实先于友好」） |
| TD-11 | GUI 触发弹窗双通道：NDJSON + `~/.aitools/.last-migration.json` | 事件可能因 GUI 启动时序丢失，落盘文件兜底 |

## 4. 兼容性

- **从 v0.4.x 升级**：自动迁移，备份原文件为 `<file>.bak`
- **从 v0.2.0 / v0.3.x 升级**：自动迁移（`user_path` → `user_base`，补 `user_subscriptions`）
- **从 v0.1.x 或更早升级**：不支持，仍需手动重建
- **存量 `~/.claude/` 与 `~/.claude-code/` 资源**：合并到 `~/.claude-internal/`；同名内容冲突时阻断

## 5. 影响范围

新增：13 个文件（含 SSOT、迁移管线、守卫工具、组件、单测）
修改：22 个文件（CLI 5 处、desktop 4 处、Types 层、测试夹具批量替换、文档）
删除：`desktop/src/lib/tools.ts:TOOL_PROJECT_DIR_ALIASES` 双名兼容映射
依赖：无新增

## 6. 反例 / 替代方案

- **方案 A（已否决）**：把 SSOT 放在 `src/registry/tools.ts`，desktop 通过相对路径 import
  - 否决原因：跨包 tsconfig + moduleResolution 不兼容
- **方案 B（已否决）**：保留 v0.4 立场「不提供迁移工具」
  - 否决原因：用户重建成本过高；v0.4 立场基于「v0.4 是 v0.3 的破坏性重写」假设，
    在 v0.5 这种增量改进场景下不再适用
- **方案 C（已否决）**：在 `loadConfig` 之外提供独立 `aitools migrate` 子命令
  - 否决原因：用户需要主动知道迁移存在，违反透明化目标
