## 1. 背景与动机（Why）

### 1.1 现状

- RFC-001 v0.4.0 落地后，`~/.aitools/config.yaml` 的 `targets[]` 里每个 target 带一个 `enabled: boolean` 字段。
- 目前**只能手动编辑 yaml** 来改这个字段：CLI 没有任何命令去开/关一个 target。
- CLI 层面现有 5 个命令：`init` / `sync` / `list` / `subscribe` / `unsubscribe`，均不涉及 target 的启用状态。

### 1.2 触发这次 patch 的契机

在 RFC-002「GUI 订阅视图重设计」的 Q1 决议中，我们确认：

> GUI 的 Tools 页面必须有"启用/禁用 target"的开关。按 UI-over-CLI 原则，GUI 不能直接写 yaml；必须走 `invoke_cli` 调用 CLI 命令。因此 CLI 层必须补齐 `target enable/disable` 命令。

见 `docs/rfcs/v0.4.1-gui-subscription-view.md` 第 7 节 Q1 决议。

### 1.3 为什么不合进 RFC-001 原文

- RFC-001 已 🟢 Accepted 并发版（v0.4.0），不回改已归档 RFC 的正文
- 本次增量足够小（单文件量级），独立 patch RFC 更易追踪变更影响面
- 同样的模式将来也适用于 target 增删改等其他 target 操作

## 2. 目标（What）

### 2.1 硬目标

- 新增 `aitools target enable <name>` 子命令：将 `targets[?name==name].enabled` 置为 `true`
- 新增 `aitools target disable <name>` 子命令：将 `targets[?name==name].enabled` 置为 `false`
- 两命令**幂等**：重复调用不报错、不产生副作用
- 两命令支持全局 `--json` 模式，输出 NDJSON 事件
- `target` 作为**命令族**引入（`aitools target <subcommand>`），为将来的 `target add/remove/list` 预留扩展点

### 2.2 非目标

以下功能**不**在本 patch 范围内（视用户反馈再决定是否后续补）：

- ❌ `aitools target add` / `aitools target remove`（改动 targets 清单本身）
- ❌ `aitools target list`（已经通过 `aitools list --json` 间接暴露 targets 信息）
- ❌ `aitools target rename`（涉及已同步文件迁移，复杂度过高）
- ❌ `aitools project init`（RFC-002 Q2 讨论过，首版不做；若 GUI 侧阶段 4 确需要，再起小 patch）

## 3. 设计（How）

### 3.1 命令形态

```bash
# 启用
aitools target enable <name>
aitools target enable codebuddy

# 禁用
aitools target disable <name>
aitools target disable claude-code

# JSON 模式（供 GUI 调用）
aitools --json target enable codebuddy
aitools --json target disable claude-code
```

**参数约束**：

- `<name>` 为必填位置参数
- `<name>` 必须匹配 `config.targets[*].name` 中某一项；不匹配则报错退出
- 命令无其他选项（保持最小面）

### 3.2 行为语义

| 调用场景 | 结果 | 退出码 |
|---|---|---|
| target 存在，状态需要翻转 | 翻转并写回 `~/.aitools/config.yaml`，打印确认 | 0 |
| target 存在，状态已经是目标状态 | 幂等跳过，打印"无变更"提示 | 0 |
| target 不存在 | 报错并列出可用 target 清单 | 1 |
| 配置文件不存在 | 报错"请先运行 `aitools init`" | 1 |
| 配置文件存在但校验失败 | 报错（与现有 `loadConfig` 错误通道一致） | 1 |

### 3.3 CLI 注册（commander）

在 `src/index.ts` 内新增 `target` 命令族：

```typescript
/**
 * 注册 target 命令族（v0.4.2 新增 / RFC-001.1）
 * 语义：管理同步目标工具的启用状态
 * 说明：引入子命令层级，为将来 target add/remove 等操作预留扩展点
 */
const targetCmd = program
  .command('target')
  .description('管理同步目标工具（target）的启用状态');

targetCmd
  .command('enable')
  .description('启用指定 target')
  .argument('<name>', 'target 名称（如 codebuddy、claude-code）')
  .action(targetEnableCommand);

targetCmd
  .command('disable')
  .description('禁用指定 target')
  .argument('<name>', 'target 名称（如 codebuddy、claude-code）')
  .action(targetDisableCommand);
```

**commander 子命令层级说明**：`aitools target enable x` 与 `aitools subscribe skills x` 在 commander 里是两种写法——前者是 group+subcommand（两级），后者是 command+两个位置参数（一级）。引入两级层级是为 `target` 这个"管理域"预留统一前缀，符合 RFC-002 Q1 决议里"作为命令族引入"的倾向。

### 3.4 实现位置

**新文件**：`src/commands/target.ts`

```typescript
/**
 * target 命令族处理模块（v0.4.2 新增 / RFC-001.1）
 *
 * 提供启用/禁用同步目标工具的能力，填补 RFC-001 留下的空缺
 * （之前只能手改 ~/.aitools/config.yaml 的 targets[].enabled 字段）
 *
 * 参见：RFC-001.1 v0.4.2
 */
import { loadConfig, saveConfig } from '../config/manager.js';
import { reporter, isJsonMode, emitJson } from '../utils/reporter.js';

/**
 * 内部统一入口：根据目标状态翻转 target 的 enabled
 * @param name 目标 target 名称
 * @param desired 期望的 enabled 状态（true=启用，false=禁用）
 */
async function setTargetEnabled(
  name: string,
  desired: boolean,
): Promise<void> {
  const config = await loadConfig();
  if (!config) {
    if (isJsonMode()) emitJson({ event: 'done', data: { exitCode: 1 } });
    return;
  }

  /* 查找目标 target；不存在时给出可用清单引导 */
  const target = config.targets.find((t) => t.name === name);
  if (!target) {
    const available = config.targets.map((t) => t.name).join(', ');
    reporter.error(`未知的 target: ${name}`);
    reporter.info(`   可用 target: ${available}`);
    if (isJsonMode()) emitJson({ event: 'done', data: { exitCode: 1 } });
    return;
  }

  /* 幂等：已经是目标状态则跳过写盘 */
  if (target.enabled === desired) {
    const verb = desired ? '启用' : '禁用';
    reporter.info(`target "${name}" 已处于${verb}状态（无变更）`);
    if (isJsonMode()) {
      emitJson({
        event: desired ? 'target.enabled' : 'target.disabled',
        data: { name, changed: false },
      });
      emitJson({ event: 'done', data: { exitCode: 0 } });
    }
    return;
  }

  /* 翻转并落盘 */
  target.enabled = desired;
  await saveConfig(config);

  const verb = desired ? '已启用' : '已禁用';
  reporter.success(`target "${name}" ${verb}`);
  if (isJsonMode()) {
    emitJson({
      event: desired ? 'target.enabled' : 'target.disabled',
      data: { name, changed: true },
    });
    emitJson({ event: 'done', data: { exitCode: 0 } });
  }
}

/** target enable 命令入口 */
export async function targetEnableCommand(name: string): Promise<void> {
  await setTargetEnabled(name, true);
}

/** target disable 命令入口 */
export async function targetDisableCommand(name: string): Promise<void> {
  await setTargetEnabled(name, false);
}
```

### 3.5 JSON 事件契约

新增两个 JSON 事件类型（`JsonEvent` 联合类型扩展）：

| 事件 | 触发时机 | data 字段 |
|---|---|---|
| `target.enabled` | `target enable` 成功（含无变更） | `{ name: string; changed: boolean }` |
| `target.disabled` | `target disable` 成功（含无变更） | `{ name: string; changed: boolean }` |

**`changed` 字段**：`true` 表示发生了实际翻转并已落盘；`false` 表示幂等跳过（状态已经是目标态）。GUI 可据此决定是否需要刷新列表动画。

**示例输出（JSON 模式）**：

```bash
$ aitools --json target enable codebuddy
{"event":"target.enabled","data":{"name":"codebuddy","changed":true}}
{"event":"done","data":{"exitCode":0}}

$ aitools --json target enable codebuddy
{"event":"target.enabled","data":{"name":"codebuddy","changed":false}}
{"event":"done","data":{"exitCode":0}}

$ aitools --json target enable unknown
{"event":"error","data":{"message":"未知的 target: unknown","code":"TARGET_NOT_FOUND"}}
{"event":"done","data":{"exitCode":1}}
```

**错误事件**：复用 RFC-001 已定义的 `error` 事件结构（`{ message, code? }`），新增 `code: "TARGET_NOT_FOUND"`。

### 3.6 类型变更

在 `src/types/index.ts` 的 `JsonEvent` 联合类型扩展：

```typescript
export type JsonEvent =
  | { event: 'list'; data: ListEventData }
  | { event: 'start'; data: SyncStartData }
  | { event: 'progress'; data: SyncProgressData }
  | { event: 'summary'; data: SyncSummaryData }
  | { event: 'done'; data: SyncDoneData }
  | { event: 'error'; data: ErrorEventData }
  /* v0.4.2 / RFC-001.1 新增 */
  | { event: 'target.enabled'; data: TargetEnabledData }
  | { event: 'target.disabled'; data: TargetEnabledData };

/**
 * target.enabled / target.disabled 事件载荷（v0.4.2 新增）
 */
export interface TargetEnabledData {
  /** 被操作的 target 名称 */
  name: string;
  /** 是否发生了实际状态翻转（false = 幂等跳过） */
  changed: boolean;
}
```

## 5. 副作用与风险

### 5.1 和 sync 的交互

- `aitools sync` 本来就只遍历 `targets.filter(t => t.enabled)`
- 本命令只修改 `enabled` 字段，不触发同步
- 禁用一个 target **不会**清理该 target 已经同步过的目录（和当前手改 yaml 行为一致）。如果用户想清理，需要自行 `rm -rf <user_base>/<type>/`，或通过 `unsubscribe --prune` 逐资源清

**决策**：不自动清理。理由：
1. 保持单一职责（enable/disable 只管 enabled 字段）
2. 已同步的资源可能被用户其他工具依赖，自动删除风险高
3. 用户重新 enable 后，该 target 下的老内容会由下一次 sync 按 hash 比对自动对齐

### 5.2 和 subscribe 的交互

- 订阅是"资源→位置"的声明，target 只是位置的展开维度
- 禁用一个 target 后：所有用户级订阅在该 target 的展开结果为 0 行
- 重新启用后：下一次 sync 会把所有用户级订阅重新同步到该 target
- `subscribe --sync` 在 `enabledTargets.length === 0` 时会 warn 跳过（现有逻辑，不需要改）

### 5.3 配置文件并发写

- CLI 单进程，文件级原子写。GUI 多点击快速切换时，由 GUI 侧做 debounce（RFC-002 Tools 页会处理）
- 本命令**不加文件锁**（当前整个 CLI 都未加锁，保持一致）

### 5.4 回滚

本 patch 破坏面极小：

- 新增命令（不改动现有命令行为）
- 新增 JSON 事件类型（JsonEvent 是联合类型，新增不破坏旧消费者）
- 不修改配置文件 schema

如果要回滚，直接删 `src/commands/target.ts` 和 `src/index.ts` 里的注册即可。

## 8. 开放问题（Open Questions · 已决议）

**Q1 · 命令族 vs. 平铺子命令？** → ✅ **采纳 A：命令族 `aitools target enable <name>`**

决议理由：
- target 域是一个概念集合，将来可能有 `target add/remove/list`；命令族前缀给这层概念一个名字
- 平铺方案带连字符丑；动词前缀方案和 subscribe/unsubscribe 的动词空间冲突
- commander 支持良好，实现成本无差别

---

**Q2 · 是否应同时落地 `aitools target list`？** → ✅ **采纳 A：本 RFC 不做**

决议理由：保持最小面；`aitools list --json` 里 `enabledTargets` 字段已覆盖 GUI 所需的目标状态信息。若将来有 CLI 调试需求再起小 patch。

---

**Q3 · 是否给 disable 加 `--prune` 选项？** → ✅ **采纳 A：本 RFC 不做**

决议理由：§5.1 已论证不自动清理的理由。若用户需要"一键禁用并清扫"，可组合使用 `unsubscribe --prune + target disable`。
