# 需求文档：优化连接工具与 Skill 订阅关联关系

> **任务编号**：FEAT-004
> **创建日期**：2026-05-08
> **状态**：已批准（2026-05-08 通过 analysis_to_design 门禁）

---

## 1. 背景与目标

### 1.1 背景

AIToolsAssistant 桌面端目前在「项目—工具—Skill 订阅」三者关联关系上存在松耦合，导致以下三类问题：

1. **顶部标题栏新增项目时，缺少目录合法性校验**：用户可以把任意普通目录（既无 `.codebuddy` 也无 `.claude`）添加为「项目」，但这类目录与任何已连接的 AI 工具都无关，进入应用后续流程会出现「项目级订阅找不到工具配置目录」「同步无目标」等异常状态。
2. **Skills 面板的「项目级订阅」展示越界**：当前会展示所有已连接工具的同步信息，即使该工具与当前项目无关。例如项目只有 `.codebuddy`，UI 仍可能展示 `claude` 工具的项目级行。
3. **新增「项目级订阅」时写入越界**：用户在未订阅区点击订阅并选择「项目级」时，系统会把所有已连接工具都写入订阅，进而创建出 `.claude/skills` 这种本不属于该项目的工具目录。

这与产品的核心隐喻「抽屉」（每个项目只放它本来就有的工具）相违背，也违反 L2 设计原则「诚实先于友好」「明确先于惊喜」。

### 1.2 目标

让「项目」「已连接工具」「Skill 订阅」三者形成强一致的绑定关系：

- **添加项目时**：拒绝与任何已连接工具都无关联的目录。
- **展示订阅时**：项目级视图只展示该项目实际关联的工具。
- **新增订阅时**：项目级订阅只能写入该项目实际关联的工具目录。

## 2. 用户故事

| 编号 | 用户故事 | 优先级 |
|------|---------|--------|
| US-1 | 作为使用 AIToolsAssistant 的开发者，我希望添加项目时系统能识别该目录是否被任一已连接工具维护，避免我误把无关目录加入项目列表，以便保持工作区整洁 | P0 |
| US-2 | 作为同时连接多个 AI 工具（如 Codebuddy + Claude）的开发者，我希望 Skills 面板的项目级订阅区只显示当前项目实际拥有的工具，以便我快速看清这个项目「真实的同步状态」 | P0 |
| US-3 | 作为开发者，我希望为某个项目新增项目级订阅时，订阅只写入该项目实际拥有的工具目录，不会凭空创建 `.claude/skills` 这类不属于该项目的目录 | P0 |

## 3. 功能范围

### 3.1 包含（In Scope）

- [ ] **目录合法性校验规则**：定义「项目目录合法」的判定逻辑（基于已连接工具的目录约定，如 `.codebuddy/`、`.claude/` 等）。
- [ ] **添加项目时的拦截与提示**：在顶部标题栏「新增项目」流程中加入校验，校验失败弹窗阻断添加。
- [ ] **项目—工具关联模型**：当一个项目可能被多个工具维护时（同时存在 `.codebuddy` 和 `.claude`），需有明确的「该项目关联工具集合」概念。
- [ ] **Skills 面板项目级视图过滤**：项目级订阅只展示该项目实际关联的工具行。
- [ ] **新增订阅写入范围限制**：项目级订阅只在项目实际关联工具的目录下写入，不创建额外工具目录。
- [ ] **空态文案**：当当前项目没有任何已连接工具时，给出清晰提示而非空白。

### 3.2 不包含（Out of Scope）

- 全局级订阅的逻辑变更（本次只动项目级）。
- 「连接工具」功能本身的扩展（不新增工具类型）。
- 已存在的不合法项目的自动清理（仅处理新增路径）。
- CLI 同名命令的合法性校验联动（仅桌面端 GUI 范畴；如需 CLI 联动需独立任务）。

## 4. 验收标准（Acceptance Criteria）

### US-1 验收标准（添加项目合法性校验）

- [ ] **Given** 已连接工具集合为 {Codebuddy, Claude}，**When** 用户选择一个既无 `.codebuddy` 也无 `.claude` 的普通目录添加为项目，**Then** 弹窗提示「当前目录未被任何已连接的 AI 工具维护，无法添加」，且不写入项目列表。
- [ ] **Given** 已连接工具集合为 {Codebuddy}，**When** 用户选择一个仅含 `.claude` 的目录，**Then** 同样提示不合法（因为 Claude 未连接）。
- [ ] **Given** 已连接工具集合为 {Codebuddy, Claude}，**When** 用户选择一个含 `.codebuddy` 的目录，**Then** 添加成功，且该项目「关联工具集合」= {Codebuddy}。
- [ ] **Given** 目录同时含 `.codebuddy` 和 `.claude`，**When** 添加，**Then** 关联工具集合 = {Codebuddy, Claude}。
- [ ] 校验**仅识别所选目录的根层级**，不递归扫描子目录中的工具目录。
- [ ] 弹窗文案符合 L2「诚实先于友好」，明确说明缺少哪些工具目录，不使用「哎呀/小问题」类卖萌词；**不提供「跳转到连接工具页面」的引导**，仅一个「我知道了 / 关闭」按钮。

### US-2 验收标准（项目级订阅展示过滤）

- [ ] **Given** 当前项目关联工具集合 = {Codebuddy}，**When** 打开 Skills 面板的项目级订阅区，**Then** 只展示 Codebuddy 的同步信息行，不展示 Claude 行。
- [ ] **Given** 关联工具集合 = {Codebuddy, Claude}，**Then** 同时展示两个工具的行。
- [ ] **Given** 项目无任何关联工具（边界场景，如目录被外部删除），**Then** 显示空态文案而不是渲染异常。
- [ ] 切换项目时项目级订阅区会随当前项目的关联工具集合刷新，不串项目。
- [ ] **Given** 项目目录中存在 `.claude/`（曾被订阅），但 Claude 此刻已被全局「断开连接」，**When** 打开 Skills 面板，**Then** 该项目下原有的 Claude 订阅条目仍然展示（不删除文件、不删除条目），但行内追加短提示「Claude 连接已断开」，且禁止再触发新的同步动作。
- [ ] 同上场景下，Claude 重新被「连接」后，提示自动消失，行恢复正常可同步状态。

### US-3 验收标准（新增订阅写入范围）

- [ ] **Given** 已连接工具 = {Codebuddy, Claude}，当前项目关联 = {Codebuddy}，**When** 在「未订阅」区为某个 Skill 选择「项目级订阅」，**Then** 只写入 `<project>/.codebuddy/skills/`，不创建 `<project>/.claude/skills/`。
- [ ] **Given** 当前项目关联 = {Codebuddy, Claude}，**When** 选择「项目级订阅」，**Then** 同时写入两个工具目录（保持现有「同步到所有关联工具」的语义）。
- [ ] **Given** 当前项目关联 = ∅，**When** 用户查看「未订阅」区，**Then**「项目级订阅」按钮**禁用**且 hover 显示 tooltip「当前项目未关联任何已连接的 AI 工具」，点击无任何写入。
- [ ] 订阅写入完成后，CLI 调用使用的 cwd 仍为用户选中的项目路径（与既有规则一致，参见项目记忆 #36043466）。

## 5. 非功能性需求

| 维度 | 要求 |
|------|------|
| 性能 | 目录合法性校验为本地文件系统判断，单次校验响应 < 100ms |
| 兼容性 | macOS 12+；行为向后兼容（不破坏既有「合法」项目的状态） |
| 一致性 | 「关联工具集合」的判定规则在 CLI 与 GUI 表现一致（GUI 只是展示与拦截层） |
| 可恢复 | 校验失败不写入任何状态，不污染 `~/.aitools/config.yaml` |

---

## 6. 约束与依赖

- **技术约束**：
  - 桌面端为 Tauri，CLI 进程 cwd 固定为 `desktop/src-tauri/`，所有依赖项目目录的判定必须显式传入用户选中路径。
  - 「已连接工具」的当前枚举来自 `~/.aitools/config.yaml`（待技术阶段确认数据源）。
  - **「项目关联工具集合」采用动态扫描**：每次需要判定时，根据「已连接工具列表」与「目标项目根层级是否存在该工具的标记目录」进行 AND 运算得出，不持久化到 `.aitools/project.yaml`。
- **外部依赖**：
  - 现有「连接工具」流程已经将工具登记到全局配置。
- **时间约束**：无强时限。

## 7. 开放问题

| 编号 | 问题 | 状态 | 结论 |
|------|------|------|------|
| Q-1 | 「项目关联工具集合」是动态计算（每次扫描目录）还是持久化在 `.aitools/project.yaml`？ | ✅ 已决策 | **动态扫描**。关联工具集合一般不变化，即使变化也应基于最新的连接工具列表重新识别，不持久化 |
| Q-2 | 校验时是否需要识别更深层级（如子目录中的 `.codebuddy`），还是仅校验所选目录根层级？ | ✅ 已决策 | **仅校验根层级** |
| Q-3 | 已连接工具被「断开」后，曾经合法的项目如何处理？是否需要在 Skills 面板提示「该项目原有的 Claude 关联已断开」？ | ✅ 已决策 | 不影响已有订阅、不删除现有文件；Skills 面板对应工具行追加短提示「Claude 连接已断开」 |
| Q-4 | 当项目关联工具为空时，「新增项目级订阅」按钮应禁用还是隐藏？ | ✅ 已决策 | **禁用 + tooltip**，保持入口可见性 |
| Q-5 | 是否需要在校验失败弹窗里提供「跳转到连接工具页面」的引导？ | ✅ 已决策 | **不需要引导**，仅提示「目录不合法」并关闭弹窗 |
